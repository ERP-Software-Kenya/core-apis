# ESLint Discipline

Follow the ESLint configs in `app/eslint.config.mjs` and `services/eslint.config.mjs` literally. Do not invent rules, do not relax them, do not add `// eslint-disable-*` to silence violations — fix the code. Run `npm run lint` in the touched package before claiming done.

## Hard limits (services/, error-level)

- Functions: max 50 lines (`max-lines-per-function`). Split, do not stretch.
- Files: max 300 lines (`max-lines`). New concern → new file.
- No `console.*` in `services/src/**`. Use the project logger.
- Identifiers: min 2 chars (`id-length`), `camelCase` only (`camelcase`). No `i`, no `x`, no snake_case.
- Every function has an explicit return type (`@typescript-eslint/explicit-function-return-type`).
- `consistent-return`, `radix`, `default-case-last`, `import/first` are errors — comply.

## Type safety (services/, error-level)

- No `any`. No `as unknown as`. No unchecked member access on `unknown`. The rules `no-unsafe-assignment`, `no-unsafe-member-access`, `no-unsafe-type-assertion` will catch these — model your code so they do not fire, do not disable them.
- Unused vars must be prefixed `_` to be ignored. Do not delete a parameter to silence the rule when the signature is fixed by an interface.
- Empty object types (`{}`) are banned (`no-empty-object-type`). Use `Record<string, never>` or a real shape.

## React / Next.js rules (app/, all error unless noted)

- `react-hooks/exhaustive-deps`: every dependency goes in the array. If a value should not retrigger the effect, refactor (ref, useCallback, move out of effect) — do not omit it.
- `react-hooks/no-deriving-state-in-effects`: derived state goes in `useMemo`, not `useEffect` + `useState`.
- `react/jsx-no-leaked-render`: never write `{count && <X/>}` — `0` will render. Use a ternary `count ? <X/> : null` or coerce `!!count && <X/>`.
- `react/no-unstable-nested-components`: never define a component inside another component's body.
- `react/jsx-no-constructed-context-values`: context `value=` must be memoized, not an inline object.
- `react/no-object-type-as-default-prop`: no `defaultProps = { x: {} }` or default-arg objects/arrays in component signatures — they create new references each render.
- `react/hook-use-state`: `const [value, setValue] = useState(...)` exactly. No `[v, set]` or `[val, update]`.
- `react/jsx-key`: every list item has a stable key. Array index keys produce warnings — do not introduce new ones.
- `react/self-closing-comp`, `react/jsx-fragments` ("syntax"), `react/jsx-pascal-case`, `react/button-has-type`, `react/iframe-missing-sandbox`, `react/jsx-no-script-url`, `react/boolean-prop-naming`, `react/no-multi-comp`, `react/no-unused-state`, `react/no-unused-class-component-methods` — comply, do not work around.

## Design tokens (app/)

- `@metamask/design-tokens/color-no-hex`: no hex literals (`#fff`, `#1a1a1a`) in JSX or Tailwind classes. Use theme color tokens.
- `@metamask/design-tokens/prefer-theme-color-classnames`: prefer `bg-background`, `text-foreground`, etc. over `bg-white`, `text-black`.
- `@metamask/design-tokens/no-deprecated-classnames`: do not use deprecated Tailwind classes flagged by the plugin.

## Ignored paths (do not lint, do not hand-edit)

- `app/src/gql/*.ts`, `services/src/gql/*.ts` — generated by codegen. Schema change → run `npm run codegen` → commit the diff. Never edit by hand.
- `services/src/workers/*.js` — generated.
- `dist/**`, `.next/**`, `out/**`, `node_modules/**`.

## Verification

- Touched a file under `app/src/**` → `cd app && npm run lint`.
- Touched a file under `services/src/**` → `cd services && npm run lint`.
- Lint output is the source of truth. Do not claim "lint passes" without running it.
